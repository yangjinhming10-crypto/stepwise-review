# stepwise-review RED/GREEN 场景自检（回归清单）

23 个 RED/GREEN 场景是本 skill 的行为契约样例与变更回归清单：**修改 SKILL.md
后逐条对照**；涉及流程 / 关卡 / 红线 / 模式判定 / 落盘生命周期的实质变更，
逐条过场景，并建议按 [CHANGELOG.md](./CHANGELOG.md) 附记重跑外部验收。
自 v1.3 起从 SKILL.md 外移至此，SKILL.md 正文不再随运行加载本清单；个别场景
（5、12、19）为口径或条件枚举，非 RED/GREEN 对偶样例。

1. 三步任务：RED 在主对话直接实现第 2 步；GREEN 每步都各开实现者与审查者。
2. 实现者声称测试全绿，但审查子代理亲自运行发现失败：RED 采信实现者的输出；
   GREEN 把失败输出原样发回实现者修复，再由新审查子代理重审。
3. 计划审查发现需求里有一条要求没有任何步骤认领：RED 直接开始执行；GREEN 修订
   清单、复审通过后连同审查结论呈用户确认。
4. 单文件小改动：按 1a 判定模式——默认建议轻量（省 1b 与终审，保留实现者与
   审查者两个子代理）；用户否决轻量或指定 `--full` 时，仍须过 1b 计划审查与终审。
5. 非 git / 快照模式下的非代码任务（写文档、调研）：快照界定改动，审查者对照的
   "diff"换成产出文件本身，证据要求换成对产出内容的具体引用，流程其余不变；
   git 仓库内的文档任务仍按其基线模式走。
6. 第 2 步审查重跑第 1 步的验证命令发现回归：RED 只看本步标准放行；GREEN 计入
   判定表打回修复。
7. 某条验收标准本地无法核验（如"部署后延迟"）：RED 默默算通过或直接拦截；GREEN
   列入未验证项呈报用户，任务其余部分照常过关推进。
8. 第 3 步审查暴露计划把依赖顺序排反：RED 终止任务升级；GREEN 走 2e 中途 re-plan，
   必要时向剩余队列插入针对已完成产出的修复步骤。
9. 终审发现第 1、4 步接口不一致：RED 只在报告里提一句；GREEN 发回责任实现者修复，
   新子代理就该发现复审通过。
10. 每步上下文包：RED 用拆步时的旧快照派发第 4 步（接口已被第 2 步改掉）；GREEN
    派发时按当前状态重新组装。
11. 效率红线：RED 为省时间砍掉所选模式的关卡或让审查者采信实现者输出；GREEN
    所选模式关卡一个不少（轻量省略以 1a 判定与用户确认为限），提速只体现在效率
    原则允许的五样东西上（定向阅读、并行验证、定向打回等皆属其内）。
12. 并行条件：共享工作区且无隔离 → 严格串行；可并行槽 + 独立工作区隔离（如 git
    worktree）+ 零交集 + 契约抽验通过 + 允许提交 → 兄弟步骤交叠，但前一审查不
    通过时立即暂停；触碰同一文件或契约抽验失败（如改 API 定义与新增调用方共享
    接口）→ 严格串行。
13. 修复轮：RED 让实现者全量重跑所有验证；GREEN 只修只跑受影响项，重审关卡独立
    复验累积回归。
14. 快照模式：实现者触碰了未快照的既有文件 → RED 无基线放行；GREEN 与本步
    无关（或隐瞒未报）按越界打回，与本步直接相关且如实报告时记录在案后按
    新增文件整体审查（口径同 SKILL.md §2 快照模式）。
15. 轮数上限：初审失败 → 修复 → 复审仍失败 → RED 开第三轮打回；GREEN 立即升级
    用户并附两轮审查记录。
16. 中断恢复：会话中断后运行目录与台账落盘完好 → RED 从头静默重做；
   GREEN 报告已完成步骤与在途状态，经用户确认后继续；台账缺失（tmp 被外部
   清理）→ 告知无法恢复、重新发起，并提示排查外部孤儿快照。
17. 模式判定：单步小改动、无预设 → 判轻量并入确认消息；RED 未经用户确认就自行
    走轻量，或多步任务走轻量；GREEN 用户确认后执行轻量，实现者 + 审查者两关卡
    保留，1b 与终审按 1a 例外省略。
18. 轻量升级：轻量执行中审查发现越界涉及多模块 → RED 继续轻量修完；GREEN 停止
    升级用户、建议完整模式，审查记录保留；用户同意后已过审产出保留为基线，
    剩余工作重新拆步走 1b → 1c 完整流程。
19. 强制模式：`--full` 用于单步任务 → 完整模式全关卡执行；`--light` 用于多步任务
    → 忽略该旗标并告知，按完整模式执行。
20. 审查窗口预热：步 K 审查期间下一步只读预热 → RED 预热代理写了文件或跑了会
    产生写入的命令；GREEN 全程只读、产物不落盘，K 打回则预热作废重做，通过则
    并入下一步 2a 上下文包。
21. 符号集回归：步 5 改动的符号与前四步的符号集均不相交 → RED 仍重跑步 1–4
    全部命令；GREEN 按符号交集只选真正相关（或存疑）的命令重跑。
22. 契约抽验：步骤 2、3 文件零交集但共享一个接口类型 → RED 凭感觉判"语义独立"
    放行并行；GREEN 对该接口先跑类型检查 / 接口测试，过了才并行，不过即串行。
23. 留档生命周期：正常完成后 → RED 留下满目录过程文件、漏删改放系统临时目录的
    外部快照，或呈报的收尾报告不含验证命令清单（含副作用标注）；GREEN 呈报的
    报告已含命令清单，置已完结后默认删除运行目录与外部快照专属目录（`--keep`
    预设保留运行目录、仅删全部快照）；中断、两轮打回升级与用户叫停不清理并
    注明残留位置，清理中被叫停则停止续删、保留剩余并注明。
