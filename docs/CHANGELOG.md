## 2026-09-02 · v1.2 —— 留档生命周期：单台账 + 完成即清

用户痛点：每次执行后项目 `tmp/` 里过程文件太多太乱，完成后大部分不再使用。

1. **一次运行一个目录**：`tmp/stepwise-review/<运行标识>/`（开始日期时间 + 任务
   简名）；台账头部记录任务描述、模式与基线模式，残留目录可自识别；新运行不写
   其他运行目录，无关残留报告用户、不自动删（§2 落盘生命周期）。
2. **单台账文件**：登记表、实现者摘要、符号集、判定表、修复记录、未验证项全部
   追加写入 `ledger.md`；快照归 `snapshots/<步骤>/`；一次运行落盘 = 1 台账 +
   快照目录，不再按步散落多文件（台账追加点在 §2 与 §2a；两处基线模式的快照
   路径同步改口径，见 §2）。
3. **收尾三态清理**：正常完成（完整模式终审闭环 / 轻量模式收尾报告呈报后）默认
   删除运行目录，删档前把**验证命令清单**并入收尾报告，保证删档后凭报告仍可
   复验；`--keep` 或用户留档要求保留 `ledger.md`（快照仍删——快照只是回滚机制，
   无档案价值）；中断、两轮打回升级、用户叫停等异常终止不清理，收尾消息注明
   残留位置（§1a、§2、§3）。
4. 新增 `--keep` 参数（frontmatter / 调用形式 / README 参数表）；场景自检增至
   23 个（新增 23 留档生命周期），场景 16 措辞对齐（运行目录与台账）。

关卡、独立性、复验义务、模式判定零改动；变更限于落盘布局与收尾清理。
复验：omp + DSH + opencode + Agy 四路独立审查（用户指定），审查对象为 v1.2 初稿，
结论与整合见下方 v1.2.1 条目。

## 2026-09-02 · v1.2.1 —— 四路审查意见整合

四路结论（对 v1.2 初稿）：omp **通过**（建议 8 条）/ opencode **通过**（建议
7 条）/ DSH **不通过**（阻断 1 条 + 建议 10 条）/ Agy **通过**（建议 3 条；
其 run1 read-only 下 command 权限被自动拒绝产出为空、run2 agent 执行异常，
run3 对内容相同的快照副本复跑成功）。阻断项与收敛建议全部收口如下：

1. **外部快照生命周期闭环**（DSH 阻断项 B1；omp S1 / opencode 1 / Agy 1 收敛）：
   台账头部记录快照位置（改放系统临时目录时记绝对路径）；正常完成删运行目录时
   按台账一并删外部快照（`--keep` 同样删全部快照）；恢复凭台账定位快照。
2. **台账头部增强与启动扫描**（omp S4/S5、DSH 4/9）：头部增记快照位置、经 1c
   确认的步骤清单与各步验收标准（re-plan 同步更新）、运行状态与最后活动时间
  （甄别活运行与陈旧残留）；每次启动先扫 `tmp/stepwise-review/*/ledger.md`，
   进行中/状态不明者报告用户确认续接或新建，台账缺失则告知无法恢复重新发起。
3. **单写者与并行标记**（omp S7、DSH 5）：台账仅由控制器追加，子代理以报告
   返回不写盘；条目显式标注步骤号；隔离区返回的验证命令改写为主区路径后登记。
4. **`--keep` 落点与时点**（omp S2、DSH 1/3、opencode 6）：留档意图须在收尾
   报告呈报前表达（`--keep` 预设或当场说明）；`--keep` 保留运行目录、仅删全部
   快照（含外部），台账可原地改名带任务标识。DSH 1 的"呈报后等用户确认再删"
   变体**未采纳**：与用户痛点（tmp 要干净）及本 skill 少交互原则冲突，以
   "报告注明已清理与留档方式 + `--keep` 预设"替代。
5. **删除健壮性**（omp S6、DSH 10、Agy 3）：清理顺序固定先快照后台账；清理中
   被叫停即停止并保留剩余（按异常终止口径）；删除被文件锁阻塞（Windows 句柄 /
   杀毒扫描）不视为任务失败，注明残留路径供手动清理。
6. **杂项**：运行标识简名限定 ASCII kebab-case、撞名追加序号（Agy 2 / omp S3 /
   DSH 2 / opencode 7）；ignore 确认上提为运行目录整体前置（opencode 4/5）；
   收尾报告验证命令清单保留副作用标注（DSH 6）；收尾三态拆为三条并列、场景 23
   措辞对齐（opencode 2、DSH 7）；README 补轻量收尾闭环与参数表目录级语义、
   frontmatter description 补 `--keep`（omp S8）；本文件 v1.2 条目 §2a 引用
   歧义修正（DSH 8）。

关卡、独立性、复验义务、模式判定仍零改动。
